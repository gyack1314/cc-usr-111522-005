# 教育资料仓层级锁的升级等待与死锁解脱资料工具

本项目提供教育数据的不可变分段行文件和现有业务操作。样本为虚构资料，不对应真实学生或学校记录。

## 现有能力

事务私有写入、提交后共享可见以及具有真实清理步骤的回滚入口。

locks.py 在事务目录之上提供进程内层级锁，与真实目录操作打通而非独立演示：

- 资源路径 `(database, table, partition)` 前缀树，锁模式 IS/IX/S/SIX/X 按标准多粒度兼容表；取子 S 自动补祖先 IS，取子 X 自动补祖先 IX，无法绕过层级。
- 同事务锁可重入，同 `request_id` 重试幂等，占用数不随重试膨胀；申请失败回收沿途句柄，不残留部分占用。
- 每资源一条 FIFO 等待队列，新请求不能越过队首冲突写者，连续读者流不会饿死已排队写者。
- 升级在等待期间保留原锁，授予后才切换或吸收子句柄，没有“先放再抢”的保护空窗；`escalate` 把表下多个分区占用原子升级为表级占用。
- 死锁检测基于真实等待图（三色 DFS），`DeadlockError` 携带实际等待环与逐资源等待边；牺牲者取持有句柄最少、身份字典序最小者，在自己的线程收到异常并经现有 `rollback_steps` 释放，回滚生成器耗尽前锁不授给别人。
- 取消与超时只撤排队项，已持有保护锁不受影响；`lock_snapshot()` 与 `wait_for_graph()` 暴露占用与等待现场。

storage.py 的 SegmentStore 将每段拆成校验页，描述文件记录页长度、SHA256与行数。扫描会真实读取页并累计bytes_read和pages_read，投影目前发生在读取整页之后，不能把少返回列误当作少读文件。

model.py 保存领域实体及约束，operations.py 的仓库读取、分区入仓、课程归档与表结构变更全部经 locks.py 取锁后再操作目录，提交/回滚在正确时点统一释放。新段身份不可覆盖，写入失败时未发布的页不出现在有效段清单中。业务字段和语义见 [CONTRACT.md](CONTRACT.md)。

## 开发与运行

运行需要Python 3.11或更新版本，无第三方包依赖。源码和数据均采用UTF-8。

```sh
python -m unittest discover -s tests -v
python -m compileall -q catalog_locks
python -m catalog_locks data/sample.json
```

命令在临时目录建段并执行已有诊断，退出后清除临时资料。数据页损坏会明确报错。测试覆盖存储校验、身份、投影及现有领域行为。
